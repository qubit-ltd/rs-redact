## 2. 基线与不变量

当前 runtime 为 `qubit-redact 0.10.0`，derive 为 `qubit-redact-derive 0.8.1`，edition 2024，MSRV 1.94。保持现有 feature 边界和依赖版本，不为本次修复调整版本号、升级依赖或发布包。

生成方案时已有未提交修改：`Cargo.toml`、`src/policy/redaction_policy.rs`、`src/runtime/redaction_handle_error.rs`。实施时先检查最新状态与差异，保留用户工作，不覆盖、不回滚、不擅自提交。行号仅是评审快照定位，实施以符号为准。

以下约束适用于所有任务：

- 保留 facade → runtime/policy、domain/formats → runtime/policy 的现有职责分层，不建立第二套公开输出模型。
- 开启脱敏时，任何完成状态都不得发布未获准的原值；修正完整性元数据不能改用原值回退。
- 每次事务或同步 Serde scope 共用现有账本，不重复准入、不预序列化测量、不重置嵌套预算。
- 保持 UTF-8 边界、日志转义和现有 Serde 事件形状；不以最终字符串长度替代真实失败事实。
- 结构化 view 与源对象的普通 Serialize 是不同边界，不能为修复 view 能力而强制添加 `#[redact(serde)]`。
- RR-V01 未证实前不改覆盖率配置、阈值、排除项或相关测试命令。
- 仅修改评审条目直接涉及的实现、测试和对应文档；不做全库风格整理、文件迁移或无关去重。
- 未经用户明确要求，不执行 `git add`、`git commit`、`git push`；本计划不授权这些操作，也不授权删除重要文件。

## 3. 方案比较与决策

选择“现有组件内修复事实传播和能力边界”。HTTP 继续返回内部结果，Serde 复用已有 projection adapter，其他条目局部处理。此方案能以明确回归证明收益。

不选择仅修改文档收窄能力承诺：它无法解决常见的 Vec/Option、借用切片需求，并会把能力断层留给下游。

不选择重写事务引擎或统一全部隐藏 Serde trait：现有预算与发布模型已有充分使用与测试依据；扩大重构将引入不必要的生命周期、coherence 和跨 crate 风险。

## 4. HTTP 完整性修正（RR-001、RR-002）

### 4.1 显式传播掩码截断

源码位置：`src/formats/http/field_redactor.rs`、`internal/form.rs`、`internal/http_policy_executor/url.rs`、`form_body.rs`。现有 `MaskingPolicy::mask_bounded_with_truncation` 已提供所需事实，不修改掩码算法或公开 `MaskedValue`。

在 FieldRedactor 增加 HTTP 内部方法：

```rust
pub(in crate::formats::http) fn redact_bounded_with_truncation<'value>(
    &self,
    field: &str,
    value: &'value str,
    max_bytes: usize,
) -> (MaskedValue<'value>, bool);
```

敏感值调用已有 masking 方法；放行值保持借用，返回 false，最终输出预算仍由调用者处理。已有仅返回文本的方法保留并委托新方法，避免扩大内部调用方迁移。规则只解析一次。

表单新增 `redact_bounded_with_truncation(...) -> (String, bool)`，现有方法可保留为兼容 wrapper。bool 表示掩码截断或编码写入拒绝，不能仅从 len 推断；一旦拒绝，停止推进后续项。`form_body` 将 bool 传给 ParsedBody 的 `rendered_truncated`。保留现有编码长度保护，不依赖 max+1 哨兵证明完整。

query 同时合并 mask_truncated、nested_truncated、pair 写入拒绝；对任一真实输出拒绝调用 writer.mark_truncated()，停止后续 query 项。最终 completion、OutputLimitReached 和 output_closed 仍由已有 writer/runtime 统一生成。

验收示例：Secret mask 为“界”、URL `https://example.test/?x=raw`、max_output_bytes=24；Secret mask 为“😀”、form `a=secret`、max_output_bytes=2。两者均不得 Complete，必须包含 OutputLimitReached，complete_text 拒绝，batch 选择 fallback。最终文本不要求保留当前错误输出，只要求安全、UTF-8 有效且不超预算。

### 4.2 disabled 不丢失来源事实

`http_policy_executor/body.rs` 的 disabled 分支将原始捕获前缀作为 ParsedBody 内容，通过现有 finish_body_redaction 终结。保持原有 raw/lossy UTF-8 与转义语义，不重新解析 body，不伪造 InvalidJson 或 UnsupportedContentType。

来源截断保留 SourceTruncated；独立输出不足保留 OutputLimitReached；两者可同时出现。usage 由原有 ingress 计量，不能再次收费。完整 capture 且输出足够仍为 Complete。disabled 本身仍表示主动恢复原值，不能因本次修复被描述为安全脱敏。

## 5. Serde 投影与切片（RR-003、RR-004）

### 5.1 以实际借用生命周期检查 projection

对 `VecProjection<'value, T>`、`OptionProjection<'value, T>` 使用：

```rust
T: RedactSerializeSource + 'value,
T::RedactedFields<'value>: Serialize,
```

元素使用 `RedactedProjectionRef::new(value, policy)`。从容器保存的 `&'value` 引用提取元素，不把借用缩成 serialize 方法的临时 self 生命周期。Some 保持 serialize_some，None 保持 serialize_none；Vec 保持序列事件与现有集合准入。空容器直接隐藏投影仍须先检查活动 scope。

兼容已有标准容器组合：旧 RedactSerialize 还支持引用、Box/Rc/Arc、固定数组和 tuple；改元素 bound 后不能让 Vec<Box<Child>>、Option<&Child> 等退化为不可用。对这些旧集合提供窄范围 RedactSerializeSource 转发：引用及智能指针直接返回内部值的 projection；数组与 tuple 使用保持原 Serde 事件和共享准入的投影。只覆盖现有支持的组合，不增加新容器种类。相关实现分别放在 internal/projection_forwarding.rs、array_projection.rs、tuple_projection.rs，按需在 internal/mod.rs 重导出供生成代码使用。

派生器 named/unnamed nested 字段的 projection bounds 与 carrier 同步改用 RedactSerializeSource、实际投影生命周期及 RedactedProjectionRef。借用字段的目标类型按现有 projection_field_type 解引用逻辑解析，不能新增全局 `for<'a>` 条件或隐含 `'static`。不通过“让所有类型无条件实现旧 hook”绕开：这可能让文本专用类型在 derive 时就被迫满足 Serialize。

### 5.2 保留源 Serialize 的既有兼容桥

旧 RedactSerialize 仍为既有手写 adapter 与 `#[redact(serde)]` 源序列化提供能力，不移除、不增加全局 blanket impl，不改公共 trait 签名。当前源 hook 通过新投影执行；迁移时必须同时检查其既有泛型能力能否推出新投影约束。

采用两种生成路径的窄适配：view projection 走新 carrier/实际生命周期；源 hook 如不能在现有 bounds 下直接委托新 projection，则用同一字段生成器的 legacy 模式生成原有结构化 body，保留原 source bounds。生成器通过明确参数选择 carrier 与 bounds，不复制独立的字段遍历算法。两条运行路径均只遍历一次、复用同一 scope、保留事件形状。

本次新增合同是“普通派生 Child 的直接、Vec、Option、nested view/to_json 均可用”，不额外扩大手写 legacy-only 子类型或源普通 Serialize 的能力范围。源 hook 兼容路径不能反向要求 view 使用旧 trait；也不能借此把源普通序列化悄然变成脱敏。对已有 `#[redact(serde)]` 的局部借用和泛型用例必须继续通过，文档说明新投影边界与源 opt-in 的区别。

测试覆盖普通 Child、借用局部 String 的 Child、泛型 Parent、无普通 Serialize 的源、已有普通 Serialize 保留原值的源，以及缺少结构化字段能力但文本可用的类型。后者的拒绝只在请求结构化输出时发生，不能落在 derive 本身。

### 5.3 level 切片

在 `domain/internal/redact_level_serialize.rs` 增加 `[T]` 的 RedactLevelSerialize 实现。切片以 serialize_seq 输出，固定数组继续 serialize_tuple，不为复用改数组协议。沿用 Vec 的结构/集合准入和 RedactedLevelSerializeRef 元素处理；拒绝后使用已有安全替代或错误合同，不创建独立预算。

验证空切片、借用 String 切片、`&str` 切片、各等级、disabled、集合/深度/输入/载荷边界及非 JSON 事件。源数据不复制、不修改。中英文指南同步明确 slice 是 sequence、array 是 tuple。

## 6. 名称与测试（RR-005、RR-006、RR-007）

raw identifier 在应用 rename_all 前统一去 `r#`。显式 serde rename 保持原样，即用户明确写出的 `r#type` 字符串不能被剥除。修正 variant 默认名称与 container 默认名称，核对相邻标签 proxy 的标识符拼接，防止 raw variant 触发无效生成标识符；只处理相同 raw 名称根因。

测试外部、内部、相邻标签和 rename_all 的 raw 变体，使用 serde_test token 验证容器名，加入原生 Serde 的对照；已有 raw 字段/keyed_by 回归继续通过。

RR-006 保留对派生源 Serialize 的测试，在遗漏处取得同文件 APPLICATION_DEFAULT_LOCK。核对同一测试二进制中读取或替换默认策略的相关测试，补齐同一锁；不为此改生产默认策略模型。必要的测试恢复 guard 仅局部使用，避免断言失败遗留全局状态。

RR-007 的三项独立断言：

1. composer：固定安装旧自定义策略，创建 composer 后替换成对同字段分类相反的新策略；比较旧 composer 与新 composer 的文本及摘要，不能只比较 redactor 对象。
2. 递归存储：调用 Redactor::standard().redact_text(&value) 并断言该输出的结构与值；保留 derive-only feature 场景，不拿普通 Debug 代替。
3. reasons：列全 12 个变体（含 FormattingFailed），逐个 singleton 对全部候选交叉断言 contains(candidate)==(inserted==candidate)，另断言 union。

这三项为测试保护能力改进，不认定对应生产实现有缺陷。不纳入评审中未进入最终意见的重复测试清理或 fixture 文案整理。

## 9. 兼容性与下游影响

不计划面向业务的签名破坏、依赖升级或大范围迁移。标准容器的已有合法组合必须保留。只手写旧隐藏 RedactSerialize、没有 RedactSerializeSource 的自定义类型，其 Vec/Option view 约束会受本次投影迁移影响：这是隐藏生成支撑能力的有限兼容性变化，不能通过重叠 blanket impl 安全兼容两种能力；这类调用方应补其借用 projection 能力，或继续在原隐藏 adapter 路径使用 RedactedSerializeRef。本项目不自动修改下游隐藏 trait 实现；实施前搜索实际下游，若发现依赖则记录具体调用方及迁移验证。HTTP 的错误 Complete 将变为真实不完整状态，下游使用 complete_text/batch marker 可能开始选择 fallback，这是修复目标；rs-http、rs-command 现有调用方式无需改变。

Serde view 支持范围扩大，普通业务 Serialize 边界保持原样。raw identifier 名称会从错误的 r#type 改为 type；如用户确实依赖旧 wire 名称，可显式 `#[serde(rename = "r#type")]` 保持旧协议。该输出兼容性变化须在实施结果和双语兼容说明中明确，不自动重命名下游数据或修改下游项目。

参考下游：rs-http 使用 diagnostic_batch 和 BodyCapture 前缀；rs-command 使用 argv/env 批次；rs-value 使用手写 Redact、keyed_nested 和 JSON 项遍历。这些现有能力不属于重构对象。下游验证使用当前检出的测试与可控临时依赖覆盖，不永久改下游 manifest，也不创建新 Paseo workspace。
