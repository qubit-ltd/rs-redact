# RR-V01 覆盖率隔离核查

## 结论

**已证实并修复。** 在覆盖率运行中的隔离 compile-test 直接启动 Cargo 时，子 Cargo 会继承 instrumentation 并产生 profile。该 profile 对应的 binary ID 不属于父覆盖率运行的 derive artifact，因此不是父报告的有效输入。三个 compile-test 使用现有 `support::isolated_cargo::command` 后，配对实验不再产生该子进程 profile。没有修改覆盖率门槛、排除配置或 helper。

## 环境和工具

- 项目 worktree：`/tmp/rs-redact-rr-20261025`。
- Rust：`rustc 1.94.0`。
- `cargo-llvm-cov`：`0.8.6`。
- 项目 infra bootstrap source revision：`00c7c1aa14ae103acf00dfb13bb06237ed585355`。
- 用于实验的独立 target/profile 根：`/tmp/rs-redact-rr-v01-target`。
- `cargo llvm-cov show-env` 列出的父进程 instrumentation 变量名包括 `CARGO_LLVM_COV`、`CARGO_LLVM_COV_BUILD_DIR`、`CARGO_LLVM_COV_SHOW_ENV`、`CARGO_LLVM_COV_TARGET_DIR`、`LLVM_PROFILE_FILE`、`RUSTC_WRAPPER` 和三个 `__CARGO_LLVM_COV_RUSTC_WRAPPER*` 变量。实验记录变量名，不保留或输出其值。

## 受控实验

单独运行 `public_api_compile_tests::test_scalar_derive_rejects_collection_fields`。该测试会创建临时 consumer 并执行 `cargo check --offline --message-format=json`。先使用原始 `Command::new(CARGO)`，再仅将该调用改为现有隔离 helper，保持相同测试、feature、target 路径和 `CARGO_NET_OFFLINE=true`；每轮先清理本实验专属 coverage target。两轮目标测试均退出码 0。

两轮父命令均为：

```text
CARGO_TARGET_DIR=/tmp/rs-redact-rr-v01-target cargo llvm-cov test --no-clean --no-default-features --features derive,serde,json --test public_api_compile_tests -- test_scalar_derive_rejects_collection_fields --exact --test-threads=1
```

原始 Cargo 调用产生 7 个 profile：父端有 3 个 profile；额外 4 个 profile 使用 binary ID `c19dcf2cfef7db1b2dd42860d02e734a6238902f`。隔离 helper 调用产生 3 个父端 profile，没有该 ID。`llvm-profdata show --binary-ids` 与 `readelf -n` 核对：worktree 的 `libqubit_redact_derive-a23f740ead9f01ce.so` build ID 为 `406ec47b204b94d45d57aabb3f08c333c3c90b86`，与额外 profile 的 binary ID 不同。额外 profile 因而来自编译 consumer 时使用的另一 derive artifact，不属于父报告所构建的 derive artifact。

两轮后执行 `cargo llvm-cov report --package qubit-redact-derive --json --summary-only`，报告摘要相同（289 个函数中 199 个覆盖，3247 行中 1824 行覆盖，4731 个区域中 2659 个覆盖），与 ID 不匹配的子进程数据未映射进父报告。第二项门槛由独立、非父 artifact profile 的实际产生及 binary ID 差异证实。

## 修复与验证

- `tests/public_api_compile_tests.rs`、`tests/feature_gate_compile_tests.rs`、`tests/map_api_compile_tests.rs` 的隔离 Cargo 创建改用已有 `support::isolated_cargo::command(OsStr::new(env!("CARGO")))`。
- 每处显式保留既有 `--offline` 行为：在 helper 初始化后设置 `CARGO_NET_OFFLINE=true`。测试参数、临时目录及诊断断言不变。
- 修复后重复受控 coverage 实验，隔离命令通过且没有子进程 binary ID `c19dcf2cfef7db1b2dd42860d02e734a6238902f` 的 profile。
- `CARGO_TARGET_DIR=/tmp/rs-redact-rr-t7-tests cargo test --no-default-features --features derive,serde,json,http,uri --test public_api_compile_tests --test feature_gate_compile_tests --test map_api_compile_tests`：通过；public API 11 项、feature-gate 6 项、map API 1 项。
- 未修改 coverage 阈值、豁免项、coverage 命令或其他隔离 Cargo 调用。
