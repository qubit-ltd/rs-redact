## 3. 总体选择与兼容性

采用逐项局部修正，保留 facade、共享 runtime、格式适配器和 Serde 投影的现有分层。不增加公开结果类型、配置项、错误变体或新的预算模型。

替代方案及取舍：

- 对 REDACT-001，复制完整准入算法到预检会产生第二套规则；优先在现有结构预算上提供最窄的只读关闭状态查询，仅在验证确有问题时让现有预检使用它。
- 对 REDACT-002，声明 Python >=3.11 可以解释环境要求，但仍让普通 Rust 测试依赖外部解释器；选择复用锁文件已有的 Rust TOML 依赖，不调整生产依赖。
- 对 REDACT-003，改成 `&mut self` 或返回原 builder 的新错误类型会改变公开调用方式；选择保留 consuming API，直接复用 owned self。
- 对 REDACT-004，全量保留所有适配器的源泛型改动最少却扩大无关约束；选择只在适配器实际使用源类型 `Self` 时保留完整源泛型，其他路径继续精确分析。

预计不需要破坏兼容性、版本升级或下游迁移。若实施证据要求改变公开签名或 wire format，应重新记录具体原因、调用方与迁移步骤，不能悄然扩大本方案。

## 4. REDACT-001：先校准可达性，再决定修复

### 4.1 证据修正

`src/runtime/runtime_core.rs` 的 `preflight_format_item`、`preflight_collection_item` 只检查额度；`src/runtime/structural_budget.rs::admit_key` 会设置 `traversal_closed`。这两点成立。

但此前“composer 的超长 field 之后追加 env，必然多调用一次 next”的推断漏看了 `src/formats/env/admission.rs::collect_environment_pairs` 在创建迭代器和循环之前执行 `admit_format_node(1)`。该调用在遍历已关闭时返回失败，能阻止所举场景。argv、process 和 domain 路径也必须连同根准入、失败返回、frame 截断一起检查，不能只从循环内语句排序推断缺陷。

因此保留稳定编号，修正可信度：公开可达副作用为待验证，不继续称已确认生产故障。实施必须先完成证据任务；不得为了符合上一轮结论而添加无实际收益的生产改动。

### 4.2 核查与条件实施

逐一检查 `src/runtime/format_admission.rs`、env/argv inspection、env admission、process 两个 admitted iterator、domain fields/items/entries 的调用链。使用具有准确非零或未知 size_hint 的计数迭代器，单独观察 `next()`；自定义 IntoIterator 时分别计量构造和推进，不扩大成“库可以阻止所有用户计算”的承诺。

用小的 `max_key_bytes` 关闭遍历，同时让节点、集合、输入及输出额度充足，避免测试意外被其他上限拦住。至少覆盖 composer、batch，以及同一 domain scope 内拒绝后的后续迭代；同时保护正常开放遍历、集合恰好用满和仅深度拒绝的现有语义。

若任何公开路径确实在关闭后推进，则在 StructuralBudget 添加最窄的 crate 内只读查询（例如 `traversal_is_closed(&self) -> bool`），由 RuntimeCore 两种预检优先拒绝关闭状态。返回 false 时沿用现有 TraversalLimitReached 记录模式；不收费、不重开遍历、不更改原始拒绝原因。开放状态继续执行现有深度和容量逻辑；深度拒绝不因此永久关闭遍历。不向外部 qubit-budget 增加接口。

若所有公开路径已被前置准入保护，则不修改生产代码，保存调用链证据并将原公开行为缺陷结论撤回。能够防止真实回归的公共契约测试可以保留；不为证明内部字段存在而增加镜像实现测试或 test hook。

## 5. REDACT-002：Cargo 测试使用 Rust TOML 解析

修改 `tests/manifest_encoding_tests.rs`，保留现有五类输入：Windows 反斜线、引号、空格、中文、换行/制表/控制字符。继续使用实际 `support::manifest::toml_string` 生成依赖路径，以真实 TOML parser 解析，再逐个精确比较 `dependencies.fixture.path` 与原字符串。

新增直接 dev-dependency `toml = "1.1.6"`，以当前锁文件 `1.1.6+spec-1.1.0` 为选择依据，实施时确认 Rust 1.94 可用；不因传递依赖已存在就直接引用未声明 crate。仅更新锁文件中与新增开发依赖直接相关的记录，禁止全量升级。

移除该测试中的 `Command`、`Stdio`、stdin 写入和 JSON 中转。以 `toml::Value` 及 `as_str()` 检查结构和字符串类型，解析失败消息包含测试 manifest。不能用自写解码器或“cargo check 接受路径”替代往返断言。

验收是该测试不需要 Python，而不是整个仓库 CI 不需要 Python。既有 Python 文档校验脚本和 project hook 继续按原职责运行。README 不必为这个已消除的依赖添加新前提；只有现有说明确实受改动影响时才同步双语文案。

## 6. REDACT-003：复用所有权并修正文档

### 6.1 consuming builder

在 `src/policy/redaction_policy_builder.rs` 的 `fields/http/uri` 内，以移动 self 到局部 draft 替换 `self.clone()`；保持现有 closure 调用、错误锁存、校验时机及 `Result<Self, PolicyError>` 签名。成功返回移动后的 builder；失败消费该值并返回错误。closure panic 仍按现有展开语义处理。

调用方需要重试时，可以事先显式克隆自己的 builder；库不默认替调用方保存可恢复副本。Rustdoc 用英文准确表述“此方法消耗 builder，失败不返回 builder；不会发布无效 policy”，不再承诺调用方能继续持有原 builder。

### 6.2 规则重建

`from_policy` 当前把 `clone_application()` 的 owned 结果再传给 `RedactionRulesBuilder::from_inner(&inner, location)`，造成第二次集合 clone。

在 `src/policy/redaction_rules_builder.rs` 添加 crate 内 owned 构造入口 `from_owned(inner: RedactionPolicyInner, location: PolicyLocation) -> Self`，移动 sensitive、allow_exact、allow_suffix 等集合。原 `from_inner` 保留现有借用签名，可委托 `from_owned(inner.clone(), location)`。`from_policy` 改用 `from_owned(policy.rules().clone_application(), PolicyLocation::Rules)`，保持唯一自然所有者与现有调用方兼容。

不得为这一优化新增公开规则层访问器、修改 floor 合并语义或批量改变其他 builder。

### 6.3 验证与文档

通过公开 policy 测试验证：链式配置保留既有 namespace；invalid fields/http 仍返回相同 PolicyError；`to_builder().build()` 保留 matching、allow、floor、unknown fallback、HTTP/URI 配置，原 policy 快照不变。

不增加与 clone 语句逐行对应的脆弱测试，不设置未测量的性能百分比门槛。收益以“去除可见冗余复制，保持行为”描述。同步修正 `doc/user_guide.md`、`doc/user_guide.zh_CN.md` 中“错误后 prior builder 不变”的表述；若常驻 design.md/design.zh_CN.md 或其他公开文档存在同一承诺，仅修正对应段落。

## 7. REDACT-004：泛型 Self 适配器验证门槛

评审答复中的文件链接有一处目录错误，实际路径是 `derive/src/serde/source_function_path.rs`，不在 `serde/internal/` 下。相关位置为 `derive/src/serde/entry.rs::adapter_helper` 与 `derive/src/expand/assertions.rs::generics_for_field_and_adapter`。

新增最小正向 fixture：泛型 `Record<T>`，`value: u32` 使用 `#[serde(serialize_with = "encode::<Self, _>")]`，另有 `PhantomData<T>`。encode 的 C 泛型真实引用源类型，返回确定数值。对原生 Serde 派生建立等价对照，再验证 Redact 的源 `#[redact(serde)]`、borrowed view 以及 `to_json`（json feature 下）序列化结果；至少显式实例化一个 T。

若原生 Serde 也不支持该输入，或现有 Redact 已编译并输出正确，则记录证伪/未复现及实际原因，不按猜测修改生成器。不把依赖解析、工具链或资源错误算成目标故障。

证实后，递归检查适配器路径中实际使用的源类型 Self，而不局限首段；覆盖路径泛型参数、限定类型、引用、元组等现有 rebind 支持形态，不把字符串和无关标识符匹配成 Self。遇到 Self 保留 source_context.generics（含必要 where 条件）；无 Self 时保留现有精确泛型提取，避免新加无关 trait bound。保持 fresh lifetime/identifier、carrier 参数传递及单次序列化行为。

相关帮助函数放在现有自然所有者文件，不拆分整个 entry.rs，不调整宏支持范围。既有 adapter_path_generics、adapter_self_path、adapter_self_predicate 等 fixture 必须继续通过。按证实的使用边界同步双语用户指南/derive README 的相关句子，避免暗示支持所有任意 Self 表达式。

## 8. 下游与验证策略

实施按“证据或失败回归 → 最小修改 → focused 通过 → 单次集中集成”推进。集成统一运行现有项目验证入口，覆盖当前 workspace 两个 crate、28 种 runtime feature 闭包、Clippy、rustdoc/doctest、双语示例、独立 fuzz 与 coverage；不得重复启动多个全量流程争用 target。coverage 不降低门槛或新增豁免。每项记录命令、退出码及故障归因，外部工具失败不能冒充目标缺陷。
