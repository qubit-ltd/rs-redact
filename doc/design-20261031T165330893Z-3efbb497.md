## 2. 已知证据

### 2.1 RR-01

- `src/domain/internal/redacted_json_serialize_ref.rs` 的 `Serialize::serialize` 仅建立 `RedactSerializeScope`，然后分派到 `RedactJsonSerialize`，没有统一结构准入。
- `src/domain/internal/redact_json_serialize.rs` 中的 `Option<T>` 实现直接发送 `serialize_some` / `serialize_none`，不为 Option 层计节点或深度。
- 同文件 `serialize_json_text` 的 disabled 分支只执行输入及载荷计量，未为字符串叶子计节点或深度。
- `doc/user_guide.md` 预算章节及对应中文版明确规定 Option 层参与结构计量，disabled 不绕过通用结构限制。
- 评审阶段的仓库外 consumer 已复现：根对象占满 `max_nodes(1)`、`max_depth(1)` 后，JSON `None`、`Some(None)` 仍输出 `null`；disabled JSON 字符串仍输出完整字符串。disabled 字符串在 `to_json`、直接 view 及派生源对象 Serialize 中均复现。
- `tests/option_projection_admission_tests.rs` 已覆盖普通嵌套 Option；此次缺口是 JSON 模式的专属路径。

### 2.2 RR-02

- `RedactionLimits` 持有通用 `StructureLimits` 和独立 `JsonValueLimits`；builder 分别提供 `max_key_bytes` 和 `max_json_key_bytes`。
- `max_key_bytes` 的 rustdoc 表述为分类前的结构键字节限制，但没有明确排除 JSON。
- JSON 文本的 `JsonStructureVisitor::visit_map` 和借用树的 `JsonUsageVisitor::enter` 未调用通用键准入；JSON 自身键限制另由 JSON budget 执行。
- 评审阶段设置 `max_key_bytes(1)` 时，`{"longkey":"visible"}` 在 JSON 文本和 Value 入口返回 Complete；同名表单键被拒绝。
- 下游 rs-http 组合使用 HTTP URL、headers、body；rs-value、rs-metadata 使用手写领域入口；rs-model-metadata 启用 derive/serde/json。作用域说明应支持这些跨入口集成，不能以改写下游替代库契约修正。

本阶段仅复读源码和文档，没有重新执行行为探针。以上运行证据属于前一评审阶段；实施前必须复现，不能视为修复后的验证结果。

## 3. 方案选择

采用局部准入修复，继续使用 `RedactSerializeScope`、`serialize_structured`、现有节点 guard 和载荷计量。保留两个执行账本，不修改公共 API、derive 语法或 feature 图。

比较过的替代方案：

1. 给 `RedactedJsonSerializeRef` 无差别包一层 `serialize_structured`：代码短，但 Value 和启用策略的 JSON 文本已有树节点计量，会重复计费，故不采用。
2. 重写通用 Serde 准入框架、合并文本与 Serde 账本：范围和兼容风险明显大于本轮收益，不采用。
3. 只改文档承认漏计：无法兑现已经明确的通用结构预算契约，不用于 RR-01。

RR-02 与 RR-01 分开裁决。优先保留现有 JSON 专属键限制；只有核查得到明确的通用键限制覆盖 JSON 的契约证据，才启用第 5 节的修复分支。

## 4. RR-01 详细设计

### 4.1 Option 层拥有自己的节点

修改 `RedactJsonSerialize for Option<T>`：通过 `serialize_structured(serializer, policy, closure)` 包裹现有 match。每个 Some/None 各占一个节点和一层深度；Some 的子值继续使用 `RedactedJsonSerializeRef`，不增加集合项计量。引用、Box 等纯转发层保持原行为。

拒绝时复用现有 Secret opaque replacement；replacement 继续经过逻辑载荷计量，无法容纳时传播 serializer 错误。拒绝的 Some 不得调用子值序列化。guard 在正常返回、错误和 unwind 时均按原机制释放深度，不重置累计节点。

### 4.2 disabled JSON 字符串只计实际字符串叶子

将 `serialize_json_text` 的 disabled 分支放到专属结构准入内，先准入字符串节点，再执行一次原有输入准入和 `serialize_payload`。不得解析 disabled 原字符串，也不得按其看起来像 JSON 的内部内容计树节点。

启用脱敏的路径继续使用既有 JSON preflight、严格解析和 `admit_structured_json_value`，不在它的外层另加重复节点。Value 路径继续由 `BudgetSerialize` 负责其实际 Serde 节点，本次不再套统一根节点。

### 4.3 可观察结果

对于根对象内的 JSON Option 字段：根对象深度为 1；None 需要第二个节点，深度为 2；Some(None) 的两个 Option 需要累计三个节点，深度为 3。每项分别测试节点不足与深度不足，避免两个限制同时配置掩盖另一个缺陷。

对于根对象内的 disabled JSON 文本字段：根与字符串叶子共两个节点，最大深度为 2。额度为 1 时采用安全结构替代；额度为 2 且字节额度充足时保持原字符串。该规则适用于 String、str 引用和 Cow 的共同入口，不增加新所有权转换。

预算足够时保留 Some/None 事件、字段名、JSON 字符串 wire type 和 Value 的结构 wire type。结构拒绝不伪造输入或输出超限原因；Serde 当前接口仍返回已有 serializer 结果，不新增摘要 API。

## 5. RR-02 核查与裁决门槛

实施任务首先复现独立限制：只设置通用键限制、只设置 JSON 键限制、同时设置且大小相反。覆盖 ASCII、UTF-8 多字节键、转义键，以及 JSON 文本、Value、HTTP JSON body、派生 JSON 字段。控制组使用 URI 查询键与 HTTP form，确认差异不是探针配置错误。

核查 `git log -S` / `git show` 中引入限制的设计、提交和回归测试，以及当前 rustdoc、双语指南对 shared structure 的具体限定。记录证据路径与提交；历史缺失本身不证明应收紧行为。

裁决规则：

- **分支 A（默认，保持兼容）：** 未找到明确要求通用键限制也覆盖 JSON 的权威项目契约，或者证据明确各自独立，则保留行为，澄清 `max_key_bytes` 与 `max_json_key_bytes` 的入口范围。加入精简的对照测试，证明 JSON 受专属限制约束。RR-02 结案为“作用域已核实并文档化”，不是“已修复缺陷”。
- **分支 B（证据触发）：** 历史规范或明确测试契约要求通用键限制覆盖 JSON，且没有后续明确变更，则认定预算缺口。JSON 分类键同时满足两项上限，取较小值。补文本和 Value 的共享键准入，并在 Serde JSON 路径保持同一作用域；不得以放宽 JSON 专属限制实现一致性。为每个入口先增加失败回归，再修改实现。

分支 B 的限制在原始键解码为 UTF-8 后、规范化和分类前检查；例如 `\u0061` 解码为一字节 a，多字节 Unicode 按 UTF-8 长度计量。通用键拒绝沿用当前结构拒绝合同，不引入新错误类别。文本分派和借用树路径各自在既有准入阶段检查，避免渲染时才发现超限；不为未序列化的隐藏字段增加与本轮无关的分类工作。disabled 路径按它实际执行的通用结构准入合同处理，不为保密已关闭的原 JSON 文本新增解析。

如果历史证据明确相互冲突且按版本先后仍无法确定，仅将 RR-02 标为未解决并说明冲突；RR-01 继续实施，最终不得把 RR-02 宣称已修复。只有真实影响方向的未决问题才向用户澄清，不等待非阻塞偏好或重复确认采纳范围。

## 7. 兼容性与迁移

不改公开类型、方法签名、feature、依赖版本或序列化成功时的表示。RR-01 会收紧过小节点/深度额度下的行为，属于兑现现有预算契约：受影响的调用方是使用 JSON Option 或 disabled JSON 文本且额度恰好依赖漏计的调用者。迁移时为每层 Option 及 disabled 文本叶子预留节点/深度，或接受安全替代及已有错误；不得通过关闭脱敏规避限制。

RR-02 分支 A 无行为迁移；调用方需同时配置 JSON 专属上限时，手册提供对应示例。分支 B 可能使超出通用键上限而此前成功的 JSON 输入被拒绝；下游在其业务准入允许范围内调整相应上限，并保持专属 JSON 上限。实施者记录分支与受影响入口，更新两种语言的说明；不批量修改下游，也不自动升级 crate 版本或发布。
