## 3. 总体取舍

选用三个局部改动及一个证据门控核查，避免引入新的公开配置、运行时层、缓存或跨调用状态。

| 可选方向 | 收益与代价 | 结论 |
| --- | --- | --- |
| 直接借用 opaque mask、JSON 同引用复用，补齐现有契约 | 消除可证明的复制/分类冗余，影响面小 | 采用 |
| 新增统一预算抽象、统一改写所有 format executor | 影响多种准入单位，缺少本轮必要性证据 | 不采用 |
| 限制自定义掩码配置大小、强制关闭自动递归、直接累计所有 domain key | 会改变已有可观察行为，不能替代根因处理或疑点核查 | 不采用 |

## 4. RR-01：借用掩码，复用原有 multipart 输出拒绝路径

### 4.1 证据

`src/formats/http/internal/multipart.rs` 的 `redact_part` 在敏感字段且 body 非 UTF-8 时调用 `mask_opaque(level).to_owned()`。后续才累计 value、转义 name 和等号的长度，并与剩余输出预算比较。固定掩码可任意长，因此很小的输入和输出预算也会触发随掩码长度增长的临时复制。

已有 `tests/multipart_allocation_tests.rs` 具备线程局部分配计数工具；`tests/http/internal/multipart_tests.rs` 的极小预算用例会在前缀写入阶段退出，不能证明此分支受控。

### 4.2 最小实现

在 `redact_part` 的 UTF-8 解码失败分支，将完整复制改为借用：

```rust
Err(_) => (
    Cow::Borrowed(redactor.masking().mask_opaque(level)),
    false,
    false,
),
```

保持函数签名、`passed`/`truncated` 元组含义、后续 `checked_add`、name 转义计长、`line_len > max_output_bytes` 和最终 `format!` 顺序不变。借用仅存在于本次调用内，最终字符串只在完整行可保留时分配。

不首选 `mask_opaque_bounded`：该 helper 返回前缀而不携带本分支完整截断事实；直接替换可能错误地把部分掩码视为完整输出。借用完整掩码并保留现有拒绝路径即可消除冗余分配，无须修改 helper 或新增公共接口。

### 4.3 验收

- 相同小输入，预构造 64 KiB、1 MiB 固定 Secret 掩码，输出预算 64 字节；在 policy、redactor、body 和预热构造完成后开始计数，两者渲染分配差不超过现有测试惯用的 16 KiB 容差。
- 确认输入包含有效 multipart framing 和一个名为 password、body 为 `0xff` 的无 filename part；预算足以写入 `<multipart>\n`，不能在进入待测分支之前退出。
- 超预算输出长度不超过上限，保持原有 completion 和 `OutputLimitReached` 原因；不可引入 `InvalidContentType` 等无关原因。
- 短掩码、完整行恰好可容纳及差一个字节、包含多字节字符的掩码和转义字段名均遵守原有 UTF-8/完整行语义。低预算不是内存分配的绝对上限，验收关注消除随掩码大小增长的完整复制。
- 至少核对 one-shot 与单项 batch 的输出/摘要一致性，不新增第二套发布模型。

## 5. RR-02：记录自动递归例外，不改变宏行为

### 5.1 证据与准确边界

`derive/src/expand/assertions.rs::normalize_recursive_fields` 在字段无 `redact` 属性、无 Serde `with`/`serialize_with`，且语法识别为支持的自递归形状时插入 `#[redact(nested)]`。`tests/derive_recursive_projection_tests.rs` 的 `RecursiveNode.next` 无属性，现有测试要求子节点 password 仍被替换。

绝对的“未标注字段保持普通输出”因此不完整。指南现有自递归 nested 段落未说明自动插入，也没有解释别名识别边界。

### 5.2 文档变更

修改以下现有文档的相关段落，保留其他内容与结构：

- `src/lib.rs`、`derive/src/lib.rs`：默认普通输出说明后紧邻补充自动递归例外。
- `README.md`、`README.zh_CN.md`：只增加精炼例外与指南入口。
- `derive/README.md`、`derive/README.zh_CN.md`：属性/能力说明补充例外和推荐显式 nested 的方式。
- `doc/user_guide.md`、`doc/user_guide.zh_CN.md`：更新默认行为表、安全边界、递归专题，给出未标注与显式 nested 的对应例子。
- `doc/design.md`、`doc/design.zh_CN.md`：说明这是 derive 的语法归一化，不是运行时根据类型猜测敏感性。

必须明确：显式 `unmarked` 与“没有 redact 属性”不同，前者不触发此自动插入；自定义 Serde adapter 也不触发；宏不解析任意别名或跨类型的任意递归图。先核对 `recursive_types`、`nested_recursion_supported` 和 `recursive_projection` 的实际形状，分别列出文本与 Serde 的支持范围，不承诺所有文本支持形状均支持 Serde。当前 Serde 投影识别包括直接递归、`Option<Box<T>>` 和 `Vec<Box<T>>`，以实施时实际代码及回归为准。

不修改自动递归行为、不新增属性、不追求双语逐句对应。示例用已有支持形状，沿用文档 runner 的 feature 标注及完整可执行块要求。已有行为测试作为依据，只在新增示例表达现有测试未覆盖的契约时追加测试，不为文字改动堆叠重复断言。

## 6. RR-03：同引用分类结果复用

### 6.1 证据

`src/formats/json/bounded_json_redaction.rs`、`serialize_redacted_value.rs` 都会将同一个 `policy.rules()` 传作 base/context；`internal/redacted_value.rs` 在每个对象键上无条件调用两次 `resolve_field`。`ResolvedField` 已实现 `Copy`。HTTP 独立上下文不能被省略。

### 6.2 最小实现

仅修改 `src/formats/json/internal/redacted_value.rs` 的对象键分类局部表达式，保持原有 match 合并逻辑：

```rust
let base = self.state.base_rules.resolve_field(key);
let context = if std::ptr::eq(self.state.base_rules, self.state.context_rules) {
    base
} else {
    self.state.context_rules.resolve_field(key)
};
let context = match (base, context) {
    (ResolvedField::Sensitive { sensitivity: base }, ResolvedField::Sensitive { sensitivity }) => {
        ValueContext::Keyed(base.max(sensitivity))
    }
    (ResolvedField::Sensitive { sensitivity }, ResolvedField::PassThrough)
    | (ResolvedField::PassThrough, ResolvedField::Sensitive { sensitivity }) => {
        ValueContext::Keyed(sensitivity)
    }
    (ResolvedField::PassThrough, ResolvedField::PassThrough) => ValueContext::PassThrough,
};
```

上面代码保留原文件的四种合并分支；实际补丁只改变 match 输入的计算。

使用对象身份判定，不能用内容相等判定，避免规则遍历开销。相同引用时每键只调用一次；不同引用即使内容相同也保持原有两次分类。无需修改 `JsonRedactionState` 构造函数和所有调用点，无需开放内部类型或增加 test hook。

### 6.3 验收与性能证据

测试覆盖同引用、不同引用、base 比 context 更强、context 比 base 更强、双方 pass-through、floor、大小写/分隔符归一化、disabled、嵌套对象与数组；序列化结果和原值不变。私有状态断言放在既有 `src/tests/formats/json/internal/json_redaction_state_tests.rs`，公开文本/Value 路径复用现有测试。

基准扩展既有 `benches/redaction_bench.rs`：固定 128 键对象，包含普通和需规范化的键，分别测 text/borrowed Value，构造放在计时外。先加工作负载获取 before，再改快路径获取 after；同一环境保留点估计和置信区间，不以 wall-clock 阈值做正确性门槛。最终只能声称消除了第二次同规则分类；无法稳定测出整体加速时如实记录，不能写推测百分比。

## 7. RR-04：先验证，按最小兼容方向明确契约

### 7.1 已知事实与尚未确认部分

`domain/internal/redacted_keyed_serialize_ref.rs` 取得动态键后只执行 `check_key_bytes`；`redact_serialize_scope.rs` 明确该检查不累计 input。文本 `redaction_fields.rs` 使用的 `RuntimeCore::admit_domain_key` 同样只检查结构键长度。不能误写成仅 Serde 有问题。

`max_input_bytes` Rustdoc 的描述较宽，但用户指南又区分 scalar/domain/Serde 准入单位。当前不能认定所有动态键必须累计计费，更不能把返回安全掩码认定为秘密泄漏。

### 7.2 核查矩阵

在 `tests/derive_serde_budget_regression_tests.rs` 补充 skipped sibling 的公开入口核查，必要时在同文件增加纯 text 用例并缩窄 feature gate。数据模型：

```rust
#[derive(Redact)]
struct KeyedHidden {
    #[redact(skip)]
    key: String,
    #[redact(keyed_by = key)]
    value: String,
}
```

覆盖 `key = "password"` 与公开键，输入预算 0、7、8、多个键总和边界；同一 sibling 被两个字段引用；sibling 未 skip 的对照；键长度上限的恰好/超限；text、view Serde、to_json。分别断言原值是否被访问/输出、是否被替换、是否返回错误及 text 摘要，不强行要求 text 与外部 Serde 拥有同一结果类型。

这些首先是观察性核查，不预设“零预算必须报错”。如果现有行为与核查结果一致，在选定契约后将关键边界保留为回归。不能为了让疑点测试失败而先修改现有预期。

### 7.3 判定规则与默认方案

1. 若实验确认分类仅受 `max_key_bytes` 限制，超限在规范化/值访问前拒绝，且没有更具体的现有兼容性承诺要求累计分类键：**保持现有计费行为**。在 `RedactionLimits` 的 max_input/max_key Rustdoc、双语指南预算段、双语设计文档写明动态分类键是单键准入单位，不单独累计进 input；若 sibling 作为普通值被输出，其值事件按原规则计费。同键引用多次不引入新去重表。这是本方案优先采用的最小兼容方向。
2. 若发现单键检查可绕过或超限前已规范化/访问值：记录可复现证据后，在具体 domain keyed 调用点修复检查顺序，并追加失败回归，不扩大到无关格式路径。
3. 只有找到并引用现有更具体的契约/测试，确实要求动态分类键累计入 input，才实施累计计费修复。计费单位定义为每次分类操作的原始 UTF-8 键字节；键作为普通输出字段的值事件是不同操作，分别计费；不按指针或内容全局去重。先单键长度、再 input admission、最后分类和值访问；text 与 Serde 同步，遵守各自安全替换/错误契约。不得直接修改通用 `admit_domain_key`，因为共享调用方可能已累计格式原始输入，必须仅在确认未计费的 domain 分类入口处理。

每个结论都要在本轮设计文档追加核查结果、命令、观察值、契约引用与最终处置；没有证据时不能把第三分支默认为修复，也不能宣称已修复缺陷。

## 8. 兼容性与下游影响

RR-01 保持输出和摘要；RR-02 只修正文档；RR-03 保持规则优先级、序列化和准入行为；RR-04 默认澄清现有单位。因此默认不新增公共 API、不改 feature、MSRV、依赖、版本及数据格式，下游无需迁移。

RR-04 若依据证据进入累计计费分支，则较低 input 预算下的动态键调用可能从成功变为安全替换/错误，属于资源边界行为收紧。已知相关调用方包括 `rs-value/src/value/redaction.rs` 的 `keyed_nested`，以及依赖这些领域对象的日志消费者；实施前只读搜索实际调用集合并记录。迁移说明应告知应用把每次分类键字节纳入预算，按结构上限估算并调整有限预算，或处理不完整结果/错误；不得建议关闭脱敏或无界提高限制。只读评估下游，不把真实下游 all-features 纳入本项目 CI。
